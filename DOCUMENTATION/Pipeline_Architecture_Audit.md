## 1. Executive Summary

**ZooMS 3D Explorer** is a lightweight, static web application designed to visualize high-dimensional proteomic data. It operates as the **Presentation Layer** for the `_ZooMS` pipeline.

**Key Architecture Decisions:**
1.  **Decoupled Data**: The app does NOT process raw data. It consumes pre-computed JSON payloads (`web_payload.json`) generated by the Python backend.
2.  **Client-Side Rendering**: All sorting, filtering, and plotting logic happens in the browser via `app.js`.
3.  **Static Deployment**: The app requires no backend server (beyond simple file serving), making it deployable on GitHub Pages or S3.

**Current Status (Critique):**
The application is functional but lacks specific analytical visualizations requested by users (specifically PPM error plots). The data contract between the Python backend and the JS frontend is currently minimal (`mz` + `intensity` only).

## 2. Core Components

### 2.1 The Viewer (`viewer.html`)
The main entry point for analysis. It expects a `?project=ID` query parameter.
- **Layout**: Split screen. Top 60% = 3D Plot, Bottom 40% = Data Table.
- **Libraries**:
    - `Plotly.js (v2.27.0)`: 3D Scatter plots & 2D Bar charts.
    - `Google Fonts`: Inter/Roboto.

### 2.2 The Controller (`js/app.js`)
Handles the application lifecycle:
1.  **Initialization**: Parses URL params -> Fetches `projects/{id}/web_payload.json`.
2.  **State Management**: Tracks `tableData`, `visibleCols`, `encodings`, and `spectraData`.
3.  **Responsiveness**:
    - `render3DPlot(data)`: Draws the UMAP cluster.
    - `renderTableRows(data)`: Draws the metadata table.
    - `highlightPoint(id)`: Syncs selection between Plot and Table.
4.  **Spectrum View**:
    - `showSpectrum(id)`: Renders a "Stick Plot" (Bar chart with width 1).

**Critical Limitation Identified:**
The `showSpectrum` function currently **only** renders the Mass Spectrum (m/z vs Intensity). It does **not** render the PPM Error plot required for QC analysis, because `web_payload.json` does not currently contain `ppm_error` data.

## 3. Data Architecture (The Contract)

The application relies entirely on `web_payload.json`. This file is generated by `_ZooMS/scripts/generate_web_data.py`.

**Current Schema (Observed):**
```json
{
  "tableData": [
    {
      "id": "StM_ET_1",
      "Species": "Ovis aries",
      "PQI": 0.85,
      "x": 12.5, "y": 4.2, "z": -1.1  // UMAP Coordinates
    }
  ],
  "encodings": {
    "Species": { "type": "categorical", "mapping": {...} },
    "PQI": { "type": "continuous", "colorscale": "Viridis" }
  },
  "spectraData": {
    "StM_ET_1": {
      "mz": [800.1, 801.1, ...],
      "intensity": [5000, 200, ...]
      // MISSING: "ppm_error": [...]
    }
  }
}
```

**Required Schema Update (Phase 2 Spec):**
To support the requested features, the schema must be expanded:
```json
"spectraData": {
  "StM_ET_1": {
    "mz": [...],
    "intensity": [...],
    "ppm_error": [2.1, -1.5, ...], // New Field
    "markers": [                   // New Field
       {"mz": 1050.5, "label": "COL1A1", "type": "Isotope"}
    ]
  }
}
```

## 4. Operational Workflows

### 4.1 Data Update Workflow
To update the data shown in the Explorer:
1.  **Run Pipeline**: Execute `_ZooMS/scripts/02_ha_Peak_Identifier.py` (and others) to generate results.
2.  **Generate Payload**: Run `python3 _ZooMS/scripts/generate_web_data.py {project_name}`.
3.  **Verify**: Check `projects/{project_name}/web_payload.json`.
4.  **Reload**: Refresh `viewer.html` in the browser.

### 4.2 Codicum Sync Workflow
**Script**: `sync_parchment_data.py`
**Purpose**: Ingests images from Google Drive, detects QR codes, and updates a Google Sheet.
**Context**: This is an *upstream* data acquisition tool. It operates independently of the visualization layer.

## 5. Audit Findings & Recommendations

### 5.1 Critical Gaps
1.  **Plots**: The "M/Z vs PPM Error" plot is missing.
2.  **Data**: `web_payload.json` lacks the underlying data to generate this plot.
3.  **Consistency**: The "Reconstructed MALDI Plot" uses a bar chart emulation (width=1) instead of a proper stem plot or line plot.

### 5.2 Next Steps (Agent Instructions)
1.  **Modify Backend**: Update `_ZooMS/scripts/generate_web_data.py` to extract `ppm_error` from `peaks.parquet`.
2.  **Modify Middleware**: Ensure `spectraData` includes the new arrays.
3.  **Modify Frontend**: Update `js/app.js` -> `showSpectrum()` to support a secondary trace (Scatter gl) for PPM error or a subplot layout.
